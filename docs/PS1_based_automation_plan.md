# DX-MV-04 — PS1方式を主軸にしたMech-Vision自動化の計画

> **作成日**: 2026-09-24
> **目的**: 繰り返し試験でのMech-Vision GUI操作をPS1（Win32 API直接クリック）方式で自動化し、トークン消費を抑えた検証体制を確立する。

## 背景

DX-MV-02で採用したPS1方式（PC-C上のWin32 APIでPC-Cの画面内のRDP画面の特定位置をクリック）は、トークン消費がほぼゼロで高速に繰り返し試験を回せる。一方、RDP越しのComputer-use方式は画像認識のためトークンを大量に消費し、繰り返し試験でトークン制限に達するリスクがある。

## 方針

| 操作 | 方法 | トークン消費 | 備考 |
|---|---|---|---|
| Mech-Visionのパラメータ変更・Run実行 | **PS1方式（固定座標クリック）** | ゼロ | DX-MV-02で実績あり |
| 成否判定（クリックがずれたか確認） | **軽量な画素比較** | ゼロ | 特定座標の画素色が変わったかだけを判定 |
| 例外処理（エラー対処等） | **RDP越しComputer-use** | あり | 頻度が低い場合のみ |

## 繰り返し試験の流れ

```
1. マスター（Hermes）が試験条件リスト（パラメータ設定値）を用意
2. PC-C上のPS1スクリプトがRDP越しにIPCのMech-Visionを操作
   - パラメータ変更 → 保存 → Run → 結果を共有フォルダへコピー
3. 各条件で成否判定（画素比較）
4. 結果をファイルシステムに出力
5. レビュー（Claude Code）が結果を確認
```

## PS1方式の弱点と対策

| 弱点 | 対策 |
|---|---|
| Mech-Visionのウィンドウサイズや表示状態が変化するとクリックがずれる | 画素比較でクリック成否を判定。ずれた場合は報告 |
| RDPの描画遅延でクリックが効かない | クリック後に画素が変わるまで一定時間待機 |
| 想定外のダイアログが表示される | 画素比較で検知 → Computer-useに切り替えて対処 |

## トークン消費の見積もり

| 項目 | 1回あたり | 100回繰り返し | 備考 |
|---|---|---|---|
| PS1スクリプト実行 | 0トークン | 0トークン | PC-C上で完結 |
| 画素比較 | 0トークン | 0トークン | PC-C上で完結 |
| レビュー（Claude Code） | 数千トークン | 数十万トークン | 結果の妥当性判断のみ |
| Computer-use（例外時） | 数万トークン | 数万トークン | 頻度が低い場合のみ |
